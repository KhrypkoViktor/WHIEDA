## Core: `POST /api/v1/content-access/crm/contacts/bulk`

- Тело `{contacts: [{name, phone?, source?}]}`, до 500 строк. Та же авторизация, что у остальных
  роутов CRM (`_context`: entitlement → сессия → пилот → PRO), все ответы `private, no-store`.
- Телефон — `split_phone` (NFKC → E.164), имя — `clean_name`, источник — `clean_source`, как
  у одиночного создания. Статус `new`, шаг `invite`, дата — сегодня по поясу аккаунта.
- Дубликаты по `phone_e164` внутри аккаунта и внутри самой пачки пропускаются и возвращаются
  в `skipped` с `contact_id` существующей (самой старой) карточки; пустое имя — `skipped` с
  `reason: name_required`, `contact_id: null`. Строки без распознанного номера дубликатами
  друг друга не считаются. Ответ `201 {ok, created: n, skipped: [{name, phone, contact_id, reason}]}`.
- Ошибки: `>500` → `400 too_many_contacts {limit: 500}`; пустой список → `400 contacts_required`;
  отказ базы → `400 invalid_input` без ПДн в логах (существующий `_PrivateRoute`).
- Одна транзакция: `_existing_by_phone` + одна вставка через `unnest` в `tenant_connection`;
  отказ на любой строке откатывает всю пачку (доказано триггером в интеграционном тесте).
- Тесты: `tests/test_crm_routes.py` (+6: 401, 402, 201 с формой ответа и тем, что уходит в
  сервис, 400 на 501 строк и на пустой список, 400 без ПДн в логах);
  `tests/test_crm_bulk_postgres.py` (дубликаты в базе и в пачке, чужой аккаунт — не дубликат,
  пустое имя, без телефона, нераспознанный номер как raw, 500 строк, повторный импорт, откат
  пачки, RLS другого тенанта).

## Сайт: экран «Добавить из телефона» (`/crm/#import`)

- Кнопка «Добавить из телефона» на «Люди» (рядом с «Добавить человека»); вкладка «Люди»
  подсвечена на `#import`.
- Android/Chrome: «Выбрать из контактов телефона» — `navigator.contacts.select(['name','tel'],
  {multiple: true})`; кнопка есть только там, где API есть. Из нескольких номеров — первый.
- «Загрузить файл (.vcf или .csv)» — везде. Разбор в браузере (`src/lib/crm/import.js`), файл
  никуда не загружается:
  - vCard 2.1/3.0/4.0, несколько визиток в файле, quoted-printable (в т. ч. мягкие переносы,
    CHARSET utf-8/windows-1251), RFC-фолдинг, экранирование, item-группы iPhone, `tel:`-URI;
    имя — FN, иначе из N (имя отчество фамилия); номер — pref → мобильный → первый;
    ORG → «откуда знакомы»;
  - CSV: разделитель `;` / `,` / табуляция и кодировка utf-8 (BOM) / utf-16 (BOM) / cp1251 —
    по файлу; с заголовком (`имя;телефон`, `name,phone`, Google Contacts «Phone N - Value»,
    Outlook «Имя»+«Фамилия», мобильный раньше остальных телефонов, организация → источник)
    и без (телефон — где похоже на номер).
- iPhone: подсказка «откройте контакт → Поделиться контактом → сохраните файл → загрузите
  сюда» (+ «Экспорт vCard» на iCloud.com для многих сразу); на других — общая подсказка.
- Предпросмотр: список с галочками (по умолчанию все, у кого есть имя; «без имени» снят и
  подписан), пустой телефон выделен золотой рамкой и подписью «телефон не указан»,
  «Выбрать всех / Снять всех», счётчик, липкая кнопка «Добавить выбранных: N» (52 px).
  До 2000 строк в предпросмотре; отправка пачками по 500 последовательно.
- Отчёт: «Добавлено: N, пропущено: M (уже есть)[, без имени: K].» + список пропущенных со
  ссылками на существующие карточки, кнопки «К списку людей» / «Сегодня». Список «Люди»
  перечитывается. Сбой посреди пачек — «Повторить» и «Добавлено до сбоя: N».
- Стили — токены и существующие примитивы (`.button-*`, `.pill-btn`, `.crm-list`), галочка
  как у согласия в формах, 24 px; hex-цветов нет (тест на канон проходит).
