## Блоки 1-2: выполнено

### Что подтверждено preflight

- `referral_profiles.ref_code` — глобальный primary key, а партнёр уже связан с
  владельцем через `owner_id -> lead_actors.actor_id`.
- У `lead_actors` есть tenant-scoped уникальность по `telegram_user_id` после
  миграции подписок. Новый код будет опираться на `actor_id`, не на поддомен,
  username или новую карту партнёров.
- В обработчике Telegram служебные маршруты идут раньше пользовательского
  текста: admin login, закрытые материалы, payment callback, платежи. После
  разбора сообщения вызываются payment-команды, затем `/start <token>`, затем
  onboarding, меню и advisor.
- Payload `ref_<invite_code>` не пересекается с существующим токеном связи
  сайта: последний принимается любым непустым `/start` token и потому Block 3
  обязан распознать `ref_` раньше `handle_start_token`.
- Существующая оплата жёстко задаёт 3 месяца в SQL и сервисе. Миграция блока 2
  снимает только SQL-ограничение и добавляет поля для выбора плана; рабочая
  команда пока остаётся трёхмесячной до отдельной правки в Blocks 4 и 7.

## Блоки 3-4: выполнено локально

- Добавлен сервис invite-кодов. Код принадлежит `actor_id`, а не username;
  смена username не ломает ссылку.
- `/start ref_<invite_code>` обрабатывается раньше обычного токена связи сайта.
  Служебные `admin_login_*` и `content_access_*` по-прежнему перехватываются
  раньше него.
- Пригласивший записывается только если у пользователя ещё нет записи
  `lead_actors` по Telegram user ID или private-chat ID. Повторный переход,
  конкурентный `/start`, самоприглашение и неверный код не меняют атрибуцию.
- После создания строки `partner_payment_ledger` в той же транзакции создаётся
  бонусный credit: 20% от W$ цены тарифа за первый денежный платёж, 10% за
  следующий. Повторный callback возвращает исходную оплату и не создаёт второй
  credit.
- Денежные платежи технически принимают срок 3/6/12 месяцев, но Telegram UI
  пока по-прежнему вызывает три месяца: выбор тарифа будет добавлен отдельным
  блоком вместе с preview-командами.

## Блоки 5-6: выполнено локально

- В Telegram добавлена команда `/referral` и компактный пункт меню `Пригласить`.
  Она регистрирует обычного пользователя бота как actor без автоматического
  пригласившего, создаёт ему один opaque invite-код и показывает ссылку,
  баланс, число приглашённых и число тех, у кого уже активен сайт.
- В сообщении есть стандартная Telegram-кнопка «Поделиться ссылкой», история
  бонусов и только те тарифы 3/6/12 месяцев, на которые уже хватает W$.
- Списание сделано через отдельный десятиминутный confirmation intent. На
  подтверждении ещё раз проверяются владелец личного сайта и баланс, затем в
  одной транзакции появляется debit в bonus ledger и продлевается сайт.
- Повторное подтверждение возвращает уже созданное списание, а не списывает
  второй раз. Отмена и истечение intent ничего не продлевают.
- Появилась добавочная миграция `platform_referral_bonus_redemptions_v2.sql`;
  staging/prod по-прежнему не изменялись.
