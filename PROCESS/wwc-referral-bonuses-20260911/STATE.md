## Блоки 1-2: выполнено

### Что подтверждено preflight

- `referral_profiles.ref_code` — глобальный primary key, а партнёр уже связан с
  владельцем через `owner_id -> lead_actors.actor_id`.
- У `lead_actors` есть tenant-scoped уникальность по `telegram_user_id` после
  миграции подписок. Новый код будет опираться на `actor_id`, не на поддомен,
  username или новую карту партнёров.
- В обработчике Telegram служебные маршруты идут раньше пользовательского
  текста: admin login, закрытые материалы, payment callback, платежи. После
  разбора сообщения вызываются payment-команды, затем `/start <token>`, затем
  onboarding, меню и advisor.
- Payload `ref_<invite_code>` не пересекается с существующим токеном связи
  сайта: последний принимается любым непустым `/start` token и потому Block 3
  обязан распознать `ref_` раньше `handle_start_token`.
- Существующая оплата жёстко задаёт 3 месяца в SQL и сервисе. Миграция блока 2
  снимает только SQL-ограничение и добавляет поля для выбора плана; рабочая
  команда пока остаётся трёхмесячной до отдельной правки в Blocks 4 и 7.
