## 1. Правила исполнения

- Делать блоки строго по порядку.
- Не начинать следующий блок, пока не выполнен его критерий готовности.
- Перед каждым изменением prod экспортировать активный workflow.
- После каждого изменения прогонять тесты блока.
- Если P0-тест упал, откатить workflow на сделанный экспорт и исправлять локально.
- Не менять сервер, базу, Dify dataset, system prompt и credentials в этом цикле.
- Не мигрировать базу и не переносить runtime в другой Postgres/Supabase.
- Не делать `sendDocument`.
- Не загружать весь архив отзывов в RAG. Для демо разрешена только небольшая проверенная подборка с source id и ссылками.
- Не развивать сейчас Problem_Solution_Matrix, бандлы и медицинские рекомендации.
- Review loop не расширять. Только проверить отсутствие регрессии в финале.
- Не менять ни один `OWNER_APPROVED_LOCKED` текст. Замечания оформлять только как `PROPOSED_CHANGE` с точным diff.
- Новые compliance-правила не применять задним числом к утвержденным карточкам без прямой команды Виктора.

## 10. Порядок после демо

Только после завершения шести блоков:

1. Testimonials MVP на 30-100 отзывах.
2. Medical review и Problem_Solution_Matrix.
3. Business review, бандлы и маркетинг-план.
4. Расширение карточек на весь каталог.
5. Ограниченный deep-слой для сложных запросов.

## 11. Definition of Done

Задача закончена только когда одновременно выполнено:

- таблица обновляет SQL по расписанию;
- топ-10 товаров полностью закрыты;
- карточка, цена, фото, видео и follow-up стабильны;
- structured-запросы не тратят LLM-токены;
- фото одно, правильное, без подписи и идет перед текстом;
- личка и группа не дают дублей;
- P0 smoke 100%;
- review smoke остается 6/6;
- тестовая админская рассылка подтверждается перед отправкой, не дублируется и имеет отчет доставки;
- готов и дважды пройден сценарий живого демо.
