# P0: заявки, рефералы и происхождение контента

## Что меняется для посетителя

- При нажатии «Заказать» заявка сохраняется в общей очереди, а не только открывается как текст в Telegram.
- Если человек пришёл по `?ref=onlineelena`, заявка закрепляется за Еленой; первый ref не заменяется последующими переходами.
- Перед отправкой видно, кому уйдёт контакт. Контакт не попадает в URL и историю браузера.
- Спам-боты отсекаются до записи заявки.

## Что видит команда

Одна очередь заявок: номер, время, товар/вариант, источник, первый ref, текущий owner и статус.
Статусы: `new` → `contacted` → `qualified` → `won` / `lost` / `spam`.
Переназначение owner не затирает исходный ref: создаёт запись в `website_lead_owner_history`.

## Что такое «статус и источник контента»

Это **внутренняя карточка материала**, а не плашка на каждой странице сайта.
Она нужна, чтобы при правке было видно: откуда взят текст и можно ли его публиковать.

Пример: текст о составе продукта — `источник: официальный материал`, `статус: согласовано`; личный опыт — `источник: отзыв`, `статус: на редактуре`; сильная рекламная формулировка — `источник: маркетинг`, `статус: согласовано`.

Поля P0: `content_id`, `tenant_id`, `source_type`, `source_url_or_file`, `status`, `owner`, `updated_at`, `notes`.
Типы источников: официальный текст / маркетинг / отзыв / исследование / внутренний материал.
Статусы: черновик / на проверке / согласовано / архив.

## Технический маршрут

`WWC форма → защищённый n8n webhook → Postgres (website_leads + audit) → уведомление назначенному партнёру в Telegram`.

Форма передаёт только POST JSON: товар, вариант, имя, контакт, комментарий, page URL, ref, first_ref, owner, tenant, idempotency key и защитные поля. Токены Telegram и SQL остаются только в n8n.
