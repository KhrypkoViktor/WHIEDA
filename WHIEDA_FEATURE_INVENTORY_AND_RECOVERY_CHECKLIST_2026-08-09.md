| Пользователи/доступ | Есть исторические таблицы и Core identity | `Users_Access`, Core | сейчас бот не должен молчать новому человеку; админский поток требует ревизии |

| Gaps/review | Очереди и staging есть | Postgres + corpus | не являются пока понятным операторским экраном |

## 2. Главный принцип ответа без «слепых зон»

Цель не в том, чтобы бот притворялся всезнающим. Цель: **никогда не бросать человека фразой «не знаю / передал на проверку» без следующего полезного шага**.

Правило маршрута:

1. Понял товар -> даёт карточку, цену, фото, видео или точное уточнение.
2. Название неполное -> предлагает до трёх конкретных вариантов, а не fallback.
3. Похоже на проблему/ситуацию -> задаёт 1-2 безопасных уточняющих вопроса и предлагает разрешённые направления, не диагноз.
4. Вопрос медицинский/опасный -> кратко ограничивает и переводит к безопасной теме: инструкция, ограничения, материалы, врачебная проверка.
5. Нет факта в базе -> говорит не «не знаю», а: «По этому нет утверждённой информации. Могу показать близкие товары / материалы / записать вопрос для точного ответа». Одновременно создаёт gap.
6. После уточнения сохраняет выбранный товар в контексте.

Нельзя:

- выдумывать показания, цены, исследования, результаты и доход;
- говорить «передал команде» как окончательный ответ;
- вытаскивать отзыв как медицинское доказательство;
- подменять карточку голой ценой или общим RAG-текстом.

## 4. Пользовательский чеклист: идём по нему и ставим факт

Статусы: `LIVE` = проверить в личке бота; `CORE` = работает в Core, но нужна ручная проверка; `DATA` = материал есть, но ещё не подан пользователю; `BLOCKED` = нужен владелец/врач/новые данные.

### A. Базовый разговор

- [ ] `LIVE` Приветствие: коротко, без видео/файлов/канцелярита.
- [ ] `LIVE` «Что ты умеешь?» показывает понятный список возможностей и пример корзины.
- [ ] `LIVE` Опечатка: `ативатор` -> правильный товар.
- [ ] `LIVE` Неполное: `активатор` -> понятное уточнение базовый/PRO, если неоднозначно.
- [ ] `LIVE` Неполное: `паста` -> зубная с полынью или Цинфэн.
- [ ] `LIVE` Цвет: `красный` -> уточнение красного эликсира; `цена красного эликсира` -> точный ответ.
- [ ] `CORE` Несколько вопросов в одном сообщении -> разделённый ответ, а не потеря второго вопроса.
- [ ] `CORE` После нормального ответа нет фразы «I have flagged it for the team» и английских артефактов.

### B. Товарный консультант

- [ ] `LIVE` Карточка каждого демонстрационного товара: Активатор, PRO, БЭМ, Вэнтун, Ба-Гуа, очки, стельки, палантин, Линчжи, Лювэй, соевый пептид, эликсиры.
- [ ] `LIVE` Карточка содержит: что это, для кого, когда смотрят, как используют, отличия, ограничения, следующий шаг.
- [ ] `LIVE` Фото: одно релевантное фото, затем отдельный текст без подписи к фото.
- [ ] `LIVE` Видео: берёт видео текущего товара из контекста.
- [ ] `LIVE` Сертификат/PDF: честно отправляет материал или говорит, что привязки нет.
- [ ] `LIVE` Цена: розница/первичка, повторка/партнёрская, PV и W$ не смешаны.
- [ ] `LIVE` Сравнение: активатор vs PRO; БЭМ vs Активатор; товары не путаются.
- [ ] `CORE` `Подробнее` даёт новый раздел, не повтор карточки.
- [ ] `DATA` Полнота материалов по всем SKU и отсутствие устаревших ссылок.

### C. Корзины, акции, бизнес

- [ ] `LIVE` `посчитай: активатор, БЭМ, Ба-Гуа` -> позиции, количества, суммы, PV, пропуски.
- [ ] `CORE` Корзина понимает «и», запятые, несколько строк, количество.
- [ ] `DATA` Оптимальный старт: сценарии регистрации, первичка/повторка, действующие акции, выгода без обещания дохода.
- [ ] `LIVE` PV, W$, повторка, бинар, Step, статусы: короткий ответ плюс предложение уточнить актуальные условия.
- [ ] `DATA` Акции РБ: срок, условия, товары, страна, источник, дата последней проверки.
- [ ] `DATA` Возражения: 20-30 быстрых ответов и глубокие варианты для коуча.

### D. Безопасность и отзывы

- [ ] `LIVE` Острый/опасный медвопрос получает безопасное ограничение и следующий шаг.
- [ ] `DATA` 109 медицинских review-пунктов готовы к врачебной вычитке.
- [ ] `DATA` 56 safety signals отделены от продающих текстов.
- [ ] `DATA` 73 выделенных отзывов имеют источник, цитату, товар и статус согласия.
- [ ] `BLOCKED` Врач подтверждает формулировки, ограничения и спорные случаи.
- [ ] `BLOCKED` Отзывы с согласием могут стать пользовательскими кейсами; без согласия остаются внутренними.

### E. Глубина и обучение

- [ ] `DATA` Dify Deep_corpus содержит 14 документов и настройки поиска.
- [ ] `CORE` Команда/режим «глубокий разбор» явно отделён от быстрого SQL ответа.
- [ ] `BLOCKED` Подключить deep mode с источниками, лимитом и запретом на выдумывание.
- [ ] `CORE` Мини-коуч «Первые 7 дней» работает как последовательность шагов.
- [ ] `DATA` Обучение по возражениям использует утверждённые quick cards и deep corpus.

### F. Лидер и оператор

- [ ] `CORE` Новый пользователь пишется в единый реестр без ручного поиска Telegram ID.
- [ ] `CORE` Админ может увидеть пользователя, его username/имя, статус доступа и отключить доступ.
- [ ] `DATA` Отчёт: активные пользователи, вопросы, SQL/RAG/fallback, gaps, заявки и заказы.
- [ ] `DATA` Лиды: ref, назначенный партнёр, статус, сумма, история.
- [ ] `DATA` Группы, встречи, сегментированные рассылки.
- [ ] `BLOCKED` Роли и права реальных лидеров, правила структуры и рассылок.

## 5. Порядок возврата к сильному продукту

1. **Проверка живого бота по разделам A-C.** Не строить новое, пока не видно, какие из уже готовых ответов реально работают.
2. **Убрать «слепые ответы».** Ввести единый controlled gap response + запись gap, покрыть смоками все старые fallback-фразы.
3. **Довести демонстрационные товары.** Карточка -> фото -> цена -> видео -> сертификат -> подробнее -> контекст.
4. **Корзина и оптимальный старт.** Сначала точный расчёт. Потом правила выгодного входа, только с актуальной акцией.
5. **Вернуть глубокий режим.** Отдельной командой, с источниками, не смешивать с SQL.
6. **Разобрать отзывы.** Сначала provenance/согласие/safety, затем кейсы и Problem -> Solution, потом бандлы.
7. **Лидерская операционка.** Пользователи, права, лиды, встречи, рассылки, отчёт.
