# Локальные инструменты корневого репозитория

Ни один из них не ходит в сеть, не требует доступов и ничего не удаляет.
Корневой репозиторий не содержит `package.json`, поэтому команды запускаются
напрямую через `node`. Подключение к общим release-скриптам сайта — задача
интегратора, а не этих инструментов.

## doc-check — проверка обязательных документов и ссылок

Проверяет, что документы из явного манифеста существуют и что их ссылки
разрешаются. Архив (`99_Archive/`) не сканируется никогда.

```bash
node tools/doc-check/check-docs.mjs
```

Выход: `0` — ошибок нет (предупреждения допустимы), `1` — есть ошибка.

Своя конфигурация:

```bash
node tools/doc-check/check-docs.mjs --manifest tools/doc-check/manifest.json
```

Тесты, включая четыре негативные фикстуры:

```bash
node --test tools/doc-check/test-doc-check.mjs
```

**Про манифест.** `knownMissing` — это запись решений, а не список подавления.
У каждой записи есть причина, по которой файла нет. Добавлять туда запись,
чтобы просто убрать красноту, — ровно то злоупотребление, против которого
инструмент и сделан. Отсутствующая ссылка не является поводом вернуть документ
из `99_Archive`: устаревший контракт, выглядящий действующим, хуже битой ссылки.

## git-snapshot — снимок Git и реестр worktree

Собирает факты из Git на момент запуска: ветка, HEAD, незакоммиченное, реестр
worktree с числом уникальных commits относительно указанной базы.

```bash
node tools/git-snapshot.mjs \
  --repo D:/Projects/WHIEDA \
  --repo D:/Projects/WHIEDA/03_Website/wwc-best \
  --base bb603a97b19af2f9e6f647d202c0eb1999bab077 \
  > PROCESS/<task-id>/GIT_SNAPSHOT.md
```

База проверяется на существование в каждом репозитории отдельно: полный
40-символьный SHA `git rev-parse` возвращает как есть, даже если такого объекта
нет, поэтому используется `rev-parse --verify`.

Колонка «Владелец задачи» намеренно всегда `unknown`. Имя ветки и автор commit
говорят, кто печатал, а не чей это срез; ни один worktree не удаляется по
возрасту или по числу commits.
